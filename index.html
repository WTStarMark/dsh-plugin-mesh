    生态图倡议书

    让每个插件被找到，也让每个作者被看见

    这张图不是排行榜，是一张"让人找到你的插件"的地图。

    01我们为什么做这件事

    DSH 的插件散落在 GitHub 的各个角落，靠标签和搜索很难被看见。我们把它们按功能铺成一张可浏览的网：找得到、点得开、装得上。

    02我们怎么收录

    • 带 dsh 系列主题标签，或仓库名里含 dsh；再按三档结论如实标注：相关 / 噪声 / 待人工复核。
    • 数据来自 GitHub 搜索接口与 npm 官方接口，每小时更新；全程只读，不写入任何第三方仓库。
    • 取不到的数据一律写「—」，绝不把"取不到"写成"0"。

    03给插件作者的三句话

    • 发到 npm，并在 package.json 里声明 dsh.bundle 或依赖 @deepseek-ai/*，这样能被自动认出来。
    • 给仓库打上 dsh-plugin 等主题标签，并在 README 开头写清"它解决什么问题"。
    • 插件住在单仓的子目录也照样收录：我们按 npm 反查加仓库内路径来认。

    04给使用者的两句话

    • 安装前看一眼仓库、许可证与最近提交时间。
    • 用得上，就去仓库点个 Star —— 星标是作者继续更新的动力。

    05我们的承诺

    不伪造数据、不刷榜、不改动别人的仓库；索引源可自由引用，本站只读。

    这一页说明本站 API 怎么调、有哪些规矩。

    01这是什么

    DSH 插件生态图的只读查询 API：三万个带 dsh 标签的 GitHub 仓库，每小时更新，无需鉴权。先调 GET /api 拿端点自述。

    02常用端点

    • GET /api端点自述与版本
    • GET /api/health数据概况：节点数、README 索引规模、生成时间
    • GET /api/categories功能扇区与细枝及各自计数
    • GET /api/repos检索仓库，支持 q / tag / category / minStars / sort / limit / offset / fields=all
    • GET /api/repos/:owner/:name单个仓库详情，含同作者与主题关联
    • GET /api/search紧凑检索：只回 id 与计数，含 README 正文命中
    • GET /api/ranking三张榜：周更新 / 周 star / 周 npm 下载，参数 days、limit、noise
    • GET /api/npm-nodes有 npm 包的仓库 id 列表
    • GET /api/review-nodes在评测站有公开测评的仓库与插件测评页链接（每 10 分钟同步；非「待复核」）
    • GET /market/index.jsonDSH 插件市场索引，format 1，可直接加进 DSH
    • GET /api/card/:owner/:name.svg可分享的仓库卡片

    03调用规矩

    • 只读、无需鉴权，但请勿高频轮询：接口按令牌计费，响应带 5 分钟公共缓存，重复拉同一份没有意义。
    • 先读 GET /api 的自述，再挑端点；批量场景用 /api/search，别逐个拉详情。
    • 请求带 Accept-Encoding: gzip：市场索引有几 MB，不压缩容易超时。
    • 遇到 429 请按 Retry-After 退避，不要并发轰炸。
    • User-Agent 标明身份与用途，方便放行与排查。

    04数据口径，别读错

    • 缺数据一律是「—」或 unknown，不是 0；把"取不到"当成 0 会得出错误结论。
    • verdict 三档：related / noise / manual；默认 noise=all 只标注、不过滤。
    • 各榜窗口互相独立：npm 的最近 7 天与 star 的 7 个自然日不一定重合，行里带窗口字段。
    • 星标与下载量都是采集时刻的快照，不是实时值。

    05引用与礼仪

    • 索引源 /market/index.json 可自由引用给 DSH 使用；转载数据请保留出处与站点链接。
    • 不要镜像全量后去掉署名，也不要用本站数据做刷榜或误导性排序。
    • 发现数据错误，欢迎到项目仓库提 issue。
