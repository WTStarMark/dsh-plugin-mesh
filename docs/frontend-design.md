# 前端设计说明（v0.2）

## 一、这一版要回答什么

生态网络的难点不是"把点画出来"，而是**在一屏里同时回答四个问题**：

1. 这个生态由哪些**功能方向**组成，各占多大分量？（扇区总览）
2. 我关心的那一类在哪？（扇区聚焦 / 过滤 / 搜索）
3. 某个仓库**凭什么**归到这一类？（规则命中词，右栏可见）
4. 哪些数据不可信？（待复核队列 + 虚线圆环）

三栏分工：左栏管"看什么"，中间管"看见"，右栏管"看懂"。

## 二、几何规则（都可测）

| 规则 | 实现 | 测试 |
|---|---|---|
| 官方仓库在圆心 | `centerId` 固定，且不参与任何扇区 | `中心固定在原点` |
| 每个功能分类一个扇区 | 分组 = `node.category`（规则判定） | `11 个功能扇区` |
| 扇区等角分布 | `angleStep = 2π/N`，首个扇区朝正上方 | `3 个分类 => 120°` |
| 扇区内离散随机散布 | 随机角度 + 半径抖动 + 松弛去重叠 | `分布必须离散自然`、`任意两节点不重叠` |
| 星标越多整体越靠近圆心 | 径向回弹到目标半径（软约束） | `星标越多整体越靠内` |
| 扇区是一束柔和的光 | 扇形裁剪 + 径向渐变 | `扇区光的裁剪生效`（冒烟测试） |
| 同数据同种子 = 同布局 | 可播种 PRNG，无 `Math.random` | `同种子逐位一致` |

散布的做法：先按星标映射出目标半径并加 ±26% 抖动、在扇区内取随机角度；再用 110 轮软松弛（分离 + 径向回弹 2%）把重叠压下去，最后 90 轮硬分离兜底。因此分布是自然离散的，而不是同心环——测试用「同一半径带内平均挤了几个节点」来识别环状，用「角度间隔的变异系数」来识别等角排列。

## 三、三个关键取舍

1. **分类用规则，不用 AI**：`tools/categories.mjs` 是打分表，可手改、可解释、可复跑、零 token。每个节点带 `categoryHits`（命中了哪些词），界面上显示出来，避免"黑箱分类"。
2. **淡化 ≠ 移除**：过滤不改变布局，任意两次观察位置可比。代价是画面上仍有淡影，界面上已写明。
3. **噪声不隐藏而是标出来**：样本里 120 个疑似噪声画虚线圆环并进待复核队列。把它们藏掉图会好看但失真。

## 四、性能

- 593 节点 / 1006 边：布局 600 次迭代约 230ms；扇区布局是一次性计算，入场动画按 `progress` 插值。
- 扇区布局复杂度 O(n)，无迭代，16981 个节点也能一次算完（渲染才是瓶颈）。
- 全量 16981 个**不能**一次画完，届时需要：取头部 + 扇区内采样 + 下钻，以及把布局搬进 Web Worker。

## 五、等你指点

1. **扇区宽度**：11 个扇区每个 29.5°，扇区偏窄、偏长（外径 250~580）。要不要把分类合并到 8 个以内换更宽的扇区？
2. **噪声内圈**：星标越近中心意味着挂标签的高星仓库会占据最内圈（`nexu-io/open-design` 99k★、`tt-a1i/archify` 75.6k★）。上一轮给的三个方案还没定：内圈只放已确认相关的 / 用相关度修正半径 / 保持现状。
3. **分类粒度**：现在 11 类，`其他` 有 54 个（9%）。要不要把「其他」再拆（例如按语言或按星标档）？
4. **时间轴 / 表格视图 / 窄屏抽屉**：要不要做？
5. **技术栈**：现在零依赖无构建。是否迁到 Vite + React/Vue？渲染层与数据契约可直接复用。

## 五点五、视觉系统：对齐 DSH

早期版本走的是"舰桥 HUD"（霓虹青、扫描线、雷达扫掠、锁定框、罗盘刻度）。方向不对：那是我自己的审美，
不是这个项目的宿主（DSH）的语言。现在改为**直接继承 DSH 主题令牌**：

- **取自 DSH 的真实值**：底色 `#151517`、卡片面 `#232324`、侧栏 `#1b1b1c`、描边 `#ffffff0f`、
  文字 `#f9fafb / #cfd3d6 / #adb2b8`、圆角 `8 / 12 / 16px`、字族为 DSH 的系统栈 + Montserrat。
- **层模型照搬 DSH**：底色 → 卡片（layer-1）→ 浮层（layer-2），hover 用 `--dsw-alias-interactive-bg-hover`。
- **画布同源**：距离环、扇区边界、节点、圆心全部用上述中性色，主色 `#5686fe`、告警 `#f59e0b`；
  去掉霓虹描边、扫描线、准星与硬质锁定框，改为柔和光点与低对比细线。
- **可验证**：`tools/dsh-tokens.mjs` 解析本机主题包 → `data/dsh-tokens.json` 留档 →
  `tests/dsh-theme.test.mjs` 逐项比对，DSH 升级后漂移会直接测试失败。

## 五点六、配色与头像（v0.5）

- **配色**：`src/palettes.js` 是唯一真源，4 套主题（清爽/粉黛 × 浅色/深色）。运行时把变量写到
  `documentElement.style`，同时把同一对象注入画布；`styles.css` 只留默认兜底，避免首屏闪色。
- **球体头像**：`src/avatars.js` 并发 6、按 URL 去重、失败不重试，只对"当前画得出来的球"排队。
  球太小（屏幕半径 < 4.5px）时仍画分类色圆点——缩小状态下头像是糊的，不如纯色点可读。
  关掉头像开关只停止绘制、不清缓存，来回切的体验是瞬时的。

## 五点七、连线规划（v0.6）

连线要同时满足**关联性**（这条线说明了什么）与**观赏性**（画出来不乱）：

| 措施 | 做法 |
|---|---|
| 关联性 | 只保留三类有解释力的边：同扇区近邻（功能相近）、同作者（同一主体）、主题共现（共享稀有主题，高频标签已排除） |
| 局部性 | 近邻只在扇区内取，长度 16~41 单位（画布半径 780），不会拉出穿场的长藤 |
| 度数上限 | 每个节点度数 ≤ 2。**不限流时实测最大度数 131**（一个大球被上百个邻居同时选中），扇区里会变成蜘蛛网 |
| 绕开圆心 | 所有连线画成背离圆心鼓起的二次曲线，交叉时从外围绕行，不在中心糊成一团 |
| 层次 | 悬停或选中时，该仓库的连线用主色提亮画在最上层，其余压暗到 18% |
| 默认值 | 默认只开「近邻 + 同作者」共 604 条；「主题共现」912 条交给用户按需打开 |

位置相关的连线**必须用布局的目标位置**（`layout.tx` / `layout.ty`），不能用入场动画中的 x / y —— 动画没跑完时它们全叠在圆心，会算出一整屏零距离的假连线（这个 bug 就是被测试抓出来的）。

## 五点八、v0.4.2：搜索放射线与完整同作者

两条"指向"的规则，都在渲染层解决，不改数据契约：

| 问题 | 做法 |
|---|---|
| 搜索命中散在圆里，看不出"结果在哪" | 命中集合（`view.setSearchHits`）在扇区光之上、节点之下画**直线 + 箭头**：从圆心直指每一个命中的仓库球；命中一多就降低透明度、不画箭头 |
| 同作者连线不完整 | 数据层为控制载荷，作者成员超过 `OWNER_CLIQUE_MAX`（8）时只存**星形拓扑**（枢纽连所有人、其余人只连枢纽），于是出现「有的能指到其余全部、有的只指到一个」 |

同作者的完整关系由 `ownerSiblings()` 从 **owner 索引**实时还原（`prepare()` / `prepareCore()` 都建 `ownerIndex`），
画布、右栏「关联」、图例计数、「只看关联仓库」四处共用同一套语义：

- 点选任意仓库 → 连到它**全部**同作者仓库（几十上百个也照画：成批建路径后一次描边）
- 图例「同作者 N」是完整计数；侧栏图例的全局数是 `ownerPairs`（完整关系对数），不再是存边数
- 右栏「关联」列出完整集合，只展示星标前 14 个并注明总数
- 查询 API `/api/repos/:owner/:name` 同步补齐同作者连线，接口消费方不会踩同一个坑

### 分类：新增「公约协议」扇区 + 16 条细枝（同一提交内）

- **公约协议**（`spec`）回答"这个生态的规则由谁定"：dsh-std 互操作元协议、社区标准、接口契约、manifest/schema 规范。
  坑是"标准/协议/公约"全是泛词（最大公约数、标准差、身高标准、HTTP 协议、DevTools Protocol、RFC 文档阅读），
  所以先过一道 **生态语境门槛**（名字本身是 std/spec/convention，或描述里出现"插件规范/生态标准/社区共识/互操作/元协议"），
  再靠精确词打分；样本天然少（本地 4 个、线上 12 个），用 `keepIds` 保证不因"样本过少"被并进「其他」。
- 扇区上限从 18 提到 20：本地因此多出 `spec` 与 `file` 两个扇区（后者原先被上限挤掉），线上还会恢复 `web`。
- 细枝新增 16 条：tools（检索搜索 / 版本控制 / 媒体处理 / 进程运行时）、agent（编码代理 / 多代理协作 / 运行时预设）、
  model（推理思考 / 参数预设 / 多模型协同）、panel（移动端界面 / 终端界面 / 创作工作台）、secure（审计扫描 / 防护拦截）+ spec（互操作协议 / 生态标准 / 接口契约）。
  本地"有扇区但没细枝"的仓库从 255 降到 178（−30%），线上从 2092 降到 1502（−28%）。

### 相关性：把"疑似噪声"拆成三档结论（同一提交内）

老口径只有一个 `review = (相关度 ≤ 2)`，本地 321 个、线上 1539 个仓库一律丢进"待复核"。
新口径 `analyze_relevance`（JS 在 `tools/relevance.mjs`，Python 在 `build.py`，逐条镜像）：

| 结论 | 判据 | 本地 | 线上 |
|---|---|---|---|
| 确认相关 | 名字/描述/主题里有 DSH 专有线索（dsh 词元 / DeepSeek Harness / Cordis） | 2437 | 17875 |
| 确认噪声 | 与 DSH 无关（只挂最宽泛的 dsh）、空壳（无描述 + 0 星）、堆标签（≥3 个标签却无插件线索）、同时铺 ≥2 个其他插件生态标签 | 93 | 416 |
| 仍需人工 | 正文像插件，但确实没提 DSH | 95 | **429**（旧口径 1539，−72%） |

前端：左栏给出三档计数与「隐藏确认噪声」开关（只隐藏已确认的那批，待复核的仍然画出来），
节点徽章从"疑似噪声"细化为"确认噪声：<原因>"与"待复核：<原因>"，待复核列表直接展示判定原因。

### 噪声黑名单（同一提交内）

同一作者被收录 **超过 200 个**仓库、且**每个仓库星标都低于 1** => 判为批量刷标签的垃圾账号：

- 采集侧（`backend/dsh_mesh/build.py` + `collect.py`）：判定后写 `data/noise-blacklist.json` 长期生效，
  `SegmentStore.merge()` 直接跳过、`drop_owners()` 把已收录的清出累积索引（下轮不再消耗配额）
- 展示侧（`src/mesh-data.js` 的 `stripNoiseOwners()`）：旧快照兜底 —— 数据文件里若还留着，
  `bootMesh` 在 `prepareCore` / `precomputedLayout` 之前剔除，并同步重排连线索引与扇区成员、改写各类计数
- 前端预计算（`tools/precompute-layout.mjs`）：产物生成前就剔除，core 与详情分片都不会有它们

`tests/owner-links.test.mjs` 对两种数据契约（mesh.json / mesh-core.json）逐个作者校验"每个仓库都能指向其余全部"，
并把"星形拓扑成员必须被补全"写成回归；`tests/app.smoke.test.mjs` 用画布桩分别数 `quadraticCurveTo`（弧线）与 `lineTo`（放射线）验证两条规则。

## 五点九、v0.4.3：协议基座、非插件排除、生态共鸣

**分类**

- 「公约协议」更名「协议基座」，收纳对象加上侧边栏底座、皮肤框架这类基座。
- 新增规则级 `strong`：命中即胜出，不再比分数。判据是 `底座|基座` 出现在名字里，或
  `基座/框架/脚手架/foundation…` 与 `插件/扩展/皮肤/面板/侧边栏/工作台…` 在 4 字符内相邻且不跨标点。
- 非插件语境排除：`NOT_PLUGIN_PATTERNS`（JS 与 Python 同步）挡掉 DSH 指别的东西的仓库。
- 桌宠补 `小鲸鱼/鲸鱼娘/娘/看板娘/mascot` 等词。

**被指向的球套光圈**

`drawTargetRings()` 在节点之上再画一层：按边类型取色（同作者=主色、主题共现=琥珀、生态共鸣=紫罗兰），
半径 `r + 3 + 槽位×2.4`；目标 ≤80 个时带外发光，同类一次 path + 一次 stroke。

`trimSegment(x1,y1,x2,y2,stopA,stopB)` 把连线两端退让到光圈外沿（目标端 `r + 3 + 槽位×2.4 + 1`，出发端 `r + 2`），
退让量按弦长一半夹住。单测在 `tests/edges-geometry.test.mjs`。

**侧栏顺序**

左栏 `renderRail`：总览 → 功能扇区 → 筛选 → 划分依据 → 捕获标签 → 高频标签（放大时第二段变「细枝分类」）。
右栏 `renderInspector`：未选中为 图例 → 操作提示 → 待复核清单；选中后改为 仓库档案 → 命中标签 → 仓库主题 → 关联 → 图例 → 操作提示。
顺序有 DOM 回归测试（`tests/panels.dom.test.mjs`）。

**共鸣开关与边类型**

每个基座可带 `enabled: false`，只停共鸣边，分类仍按基座处理；`meta.ecosystemDisabled` 记账。
`tools/curate-ecosystem.mjs` 以「生态签 ∪ 名字自述 ∪ README 搜索」取候选，逐仓抓 README 复核依赖/扩展/在用语境，
目录类排除；产物 `tools/ecosystem.json` 随代码走，构建时变成 `type: "resonance"` 的边，前端紫罗兰实线绘制。

## 五点九五、v0.4.4：改名去重（新旧两个球）

GitHub 改名后 `full_name`（节点 id）会变，数字 id 不变。旧实现丢了数字 id、累积索引又以 `full_name` 为键，
改名后新旧两条记录并存，图上就是同一个仓库两个球。

| 位置 | 改动 |
|---|---|
| `pick_repo` / `pickRepo` | 保留 `githubId`（数字 id） |
| `SegmentStore.merge` | 按 `githubId` 认人：名字不同就把旧记录挪到新名字下（记 `renamedFrom`）；新增数按索引规模增量算 |
| `build_mesh` / `buildMesh` | 同一 `githubId` 只留一个节点，取 `updatedAt` 较新的名字 |

存量迁移用 `tools/dedupe-renames.mjs`：以「同作者 + 同创建时间」筛嫌疑，逐个问 GitHub 核对数字 id 与当前名字，
同一 id 收敛为一个；只有旧名字的就地改名并改写边的两端。写盘前备份，账本记入 `data/renames.json` 与 `meta.renames`。

删过节点后要重建同作者边（原星形枢纽可能已被删），由 `tools/reclassify.mjs` 按采集器同样的算法重做。

## 五点九八、v0.4.5 / v0.4.6

**改名别名表（0.4.5）**

`data/cache/aliases.json`（旧名 → 现名，链式归一）由 `tools/dedupe-renames.mjs` 写出。
`SegmentStore` 在加载与合并时都按它归一，`build.py` 离线构建同理。
迁移工具检测到采集器在跑会拒绝执行：采集器把整份索引放内存、每 5 段回写一次，边跑边改会被覆盖。

**搜索（0.4.6）**

| 项 | 做法 |
|---|---|
| 射线上限 | 命中 > 100 只高亮、不画放射线（`RAY_HIT_LIMIT`），状态栏注明；上万条路径会让每帧卡住 |
| README 检索 | 采集器每轮补抓一批（默认 150），存检索摘要 + gzip（`data/cache/readmes.json.gz`，约 10MB/1.9 万仓库）；`GET /api/search` 只回命中 id，前端防抖 260ms 取回后并入高亮 |
| 检索实现 | 服务端把摘要拼成一个小写大字符串，`indexOf` 找位置 + 二分定位仓库 id；接口不可用时前端只用本地字段匹配 |

## 六、已知不足

- 没有无头浏览器：视觉呈现（扇区观感、标签遮挡、圈密度）未经真机验证，只验证了逻辑与不崩。
- 分类是关键词规则，会被措辞影响；`其他` 里混着"真没功能线索"和"措辞没命中"两类。
- 噪声评分是占位启发式，未做人工复核闭环。
- 边只有"主题共现"和"同作者"两类；依赖关系、README 互链、fork 血缘尚未采集。
- 抽样按星标取头部，长尾 16000+ 个仓库完全没进来。
